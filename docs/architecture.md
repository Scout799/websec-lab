最终五域HTTPS架构图见[可编辑SVG](../deliverables/figures/architecture.svg)，攻击和防御判定流程见[攻击流程](../deliverables/figures/attack-flow.svg)、[防御判定](../deliverables/figures/defense-decision.svg)。HTTPS网关终止TLS，四后端位于回环，`same.victim.test`作为同站不同源诱导别名；双通道与服务端状态分别记录。以下保留模块职责和早期结构说明。

## 设计目标

工程结构必须同时支持以下能力：

1. 本地复现多个点击劫持场景；
2. 通过配置切换安全响应头、Cookie 和业务防御；
3. 从恶意来源与合法来源分别验证页面嵌入结果；
4. 使用真实浏览器执行自动化验证；
5. 保留可用于报告的结构化证据；
6. 在不改变核心代码的情况下扩展攻击、防御和浏览器种类。

## 服务职责

### Victim

- 提供登录状态和模拟敏感业务；
- 按配置返回 XFO、CSP 和 Cookie 属性；
- 记录敏感操作是否实际执行；
- 提供仅限本地测试环境的状态查询与重置接口。

### Attacker

- 承载可控的点击劫持实验页面；
- 通过统一参数描述位置、透明度和交互步骤；
- 向实验运行器返回场景编号和执行状态。

### Partner

- 模拟合法 iframe 集成；
- 检验允许列表是否准确；
- 衡量安全策略对正常业务的影响。

### Auditor

- 静态解析 XFO、CSP 和 Cookie；
- 推导不同来源的预期嵌入权限；
- 使用 Playwright 验证浏览器实际行为；
- 生成 JSON、Markdown 和 HTML 证据报告。

## 当前阶段边界

当前只建立服务骨架、配置模型、健康检查和测试。业务状态、攻击页面、防御切换和浏览器自动化将在后续里程碑按稳定接口加入。

## 关键架构决策

### 单仓库、多服务入口

四个服务共享配置、日志和测试工具，但保留独立应用工厂，便于后续分别运行或容器化。

### 配置优先

域名、端口、存储路径和防御组合均由配置驱动。实验不得依赖临时修改源代码来切换条件。

### 证据优先

每个自动化判断都应保留响应头、控制台信息、网络记录、截图或业务状态中的至少一种证据。

### 本地优先

所有服务默认绑定 `127.0.0.1`。即使未来容器化，对外暴露范围也必须显式配置。
