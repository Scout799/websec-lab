# 项目总览：做了什么 · 怎么做的 · 主要技术特点

> 供答辩 PPT / 汇报直接取用。数据来源：`artifacts/final-matrix-v2/`（正式全量矩阵，2026-11-03，945 例）与 `artifacts/experiments/final-run/`（中期基线，20 例）。

## 一、做了什么

一句话：**构建了一个完全本地、可重复、可自动验证的点击劫持实验平台，覆盖"攻击复现 → 分层防御 → 静态分析 → 真实浏览器动态验证 → 合并报告 → 量化实验"的完整闭环。**

## 二、怎么做的

### 1. 攻击基线（无防御 → 攻击必须先"真的成功"）
victim 特意做成有真实状态变化的业务（数据库转账记录、余额、审计日志），并建立**"确认按钮精确居中"对齐契约**——攻击页 JS 把透明 iframe 的中心对齐到诱导按钮中心，点击必然落在目标确认按钮上。攻击成功不靠肉眼判断，而是用 victim 测试 API 的业务状态前后对比（转账/授权记录真实增加才算数）。七类场景在真实 Chrome 全部验证成功。

### 2. 防御矩阵（一个环境变量切换整条防线）
所有防御写进 `config/defense.yaml` 的命名 profile，victim 工厂在启动时解析并应用到响应头/Cookie/业务流程，业务代码零改动。白名单里的 `partner` 是占位符，运行时按 `lab.yaml` 展开为真实合作方来源——同一份配置在 HTTP 回环和 HTTPS 五域环境下都能用。

### 3. 静态分析（不打开浏览器，从响应头推导风险）
自研 XFO/CSP frame-ancestors 解析器：处理 DENY/SAMEORIGIN、已废弃的 ALLOW-FROM、非法值、重复头、多 CSP 交集、Report-Only、畸形指令；来源匹配覆盖 scheme/host/port/通配符；判定语义对齐 RFC 7034（SAMEORIGIN 要求全祖先链同源）与 CSP3（frame-ancestors 逐祖先逐策略校验）。输出规则编号 + 风险等级 + 修复建议 + 来源权限矩阵。

### 4. 动态审计（真实浏览器给出行为事实）
Playwright 驱动本机 Chrome/Edge/Firefox：自动登录（会话持久化）→ 探针 harness 嵌入目标 → 多信号判定 → 坐标点击诱导按钮 → 测试 API 核对业务状态 → 截图/控制台/网络/trace 证据全部落盘，失败自动保留现场。

### 5. 实验闭环（数字可复现）
每例实验独立 victim + 全新数据库；矩阵、指标、图表一条命令重跑；正式矩阵带独立复核脚本与逐例截图。

## 三、主要技术特点

1. **多信号嵌入判定**（项目最硬的技术点）：Chromium 下被阻断与成功跨域加载的 iframe 页内信号完全相同（`contentDocument` 均为 null），页内 JS 无法独立判定。我们的方案：组合**驱动侧控制台消息**（XFO→"Refused to display…"，CSP→"violates the following CSP directive…"）+ iframe load 计数 + 超时兜底 + frame-busting 弹出归类，并识别 Report-Only 消息的同文陷阱（唯一区分是 "report-only" 字样）。
2. **静态/动态双轨验证与 100% 一致率**：正式矩阵 819 组有效攻击实验（3 浏览器）中，静态响应头判定与真实浏览器行为一致率 **100%**；静态检测率 100%、漏报 0%。
3. **检测通道消融**：CSP 报告通道单独检测率仅 6.7%（27/405），页面交互通道 88.9%（360/405），双通道融合 88.9% 且覆盖尝试数从 441 提升到 657——用数据说明"报告通道只能做观测、不能做检测"。
4. **合法兼容性同实验度量**：同一矩阵同时测"恶意嵌入被阻断率"与"合作方嵌入通过率"——正确白名单两者皆 100%，XFO DENY 前者 100% 后者 0%，一组数据讲清纵深防御的代价。
5. **如实记录的边界发现**（答辩亮点）：一次性令牌挡得住重放挡不住活点击；经典 frame-busting 被现代 Chrome 无手势导航策略拦截而失效；`sandbox` 缺 `allow-same-origin` 时 SameSite=Lax 会剥离会话 Cookie（沙箱绕过必须用 `allow-forms allow-same-origin` 且仍不加 `allow-scripts`）；Report-Only 不阻断。
6. **安全边界三重实施**：抓取目标白名单（仅回环/`*.test`）、探针目标白名单、attacker 应用在非 local_only 配置下拒绝启动——整个平台不可能被指向真实网站。

## 五、一分钟演示脚本（对应录屏）

1. **恒信银行**：登录 alice，看余额与交易记录；
2. **攻击**：打开分屏演示页，点"立即领取试用装"——右侧余额实时减少、时间线逐条解说"点击落入透明 iframe → 表单提交 → 新增转账"；
3. **防御**：victim 换 `xfo-deny` 一条环境变量重启，同样的攻击页变成空白 iframe，点击毫无效果；
4. **审计**：`websec-lab audit-report` 一条命令产出 HTML 报告（结论矩阵 + 规则建议 + 攻击前后截图 + 控制台证据）。
