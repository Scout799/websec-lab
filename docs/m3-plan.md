# M3 攻击场景库实施清单

M3 的目标是在完全本地、已授权的靶场中建立可重复、可参数化、可自动验证的点击劫持场景。所有场景只能加载配置中声明的本地 `victim` origin。

## 实现说明

### victim 侧快捷目标页

- `/lab/quick-transfer`：单按钮快捷转账确认页，金额（分）与收款人可由查询参数控制并被钳制（1–50000 分，收款人回退避开当前用户）；
- `/lab/quick-grant`：单按钮快捷授权确认页；
- 两页仅在 `local_only` 环境注册路由，未登录跳转登录页；
- 确认按钮精确位于视口中心，这是攻击场景对齐协议的一部分；
- 操作写入业务审计日志（`lab.quick_transfer.executed` / `lab.quick_grant.executed`）。

### attacker 场景

| 编号 | 场景 | 说明 |
|---|---|---|
| S1 | probe | 可见加载目标并采集多信号（load 事件、contentDocument 可访问性），判定 allowed / blocked / unknown |
| S2 | overlay | 完全透明 iframe 中心对齐诱导按钮，点击落点即目标确认按钮 |
| S3 | clip | 裁剪窗口只露出目标按钮区域，覆盖在"话费充值"诱导按钮上 |
| S4 | multistep | 两步状态机：第 1 步诱导触发快捷授权，iframe 自动切换并对齐到快捷转账页，第 2 步诱导触发转账 |

### 安全与验证边界

- victim origin 只能取配置声明的来源（public_origin + 127.0.0.1/localhost 回环变体）；
- 每个场景单独限制可嵌入的 victim 路径白名单；
- attacker 应用在 `local_only=false` 时拒绝启动；
- 浏览器事件回传 API 要求 `X-Websec-Test-Token` 头，事件字段仅保留标量并限长。
