# 七类攻击场景：差异与台账指纹

> 用途：回答"七招最后都是受害者扣款，怎么证明它们不是同一个攻击换了张皮"。

## 一句话

**业务结果必须一样**——攻击成功的判定基准就是受害者账号发生了他没做过的操作。
差异不在结果，而在三处：**诱导手法、嵌入参数、受害者侧可观测信号**。
为了让演示时能当场对上号，每一招在受害者台账上记**不同金额 + 不同备注**。

## 对照表

| 场景 | 手法（与基线 S2 的差异） | 关键参数 | 台账指纹（金额 / 备注） | 点完后怎么认 |
|---|---|---|---|---|
| S1 iframe 探针 | 可见加载目标页、不覆盖、不诱导（对照组） | 透明度 1.0 | 不记账 | 只看能否嵌入与采集信号 |
| S2 透明 iframe 覆盖 | 基线：整页压到 1% 透明度盖在诱饵按钮下 | 透明度 0.01，iframe 340×360 居中对齐 | ¥1.23 / `S2 overlay` | 一笔 ¥1.23 |
| S3 界面裁剪 | 不压透明度，用裁剪窗口只露出目标按钮那一块 | 透明度 1.0 + 裁剪窗口 | ¥4.56 / `S3 clip` | 一笔 ¥4.56，且攻击页能看到目标按钮局部 |
| S4 多步连续诱导 | 两步：先切授权页点一次，再切转账页点第二次 | 两步状态机、两次切换重对齐 | ¥7.89 / `S4 multistep` + 1 条授权 | 多出一条 "Lab Partner Demo" 授权 + 一笔 ¥7.89 |
| S5 frame-busting 绕过 | 目标有 frame-busting 时加 `sandbox` 禁用其脚本，覆盖照常生效 | `sandbox="allow-forms allow-same-origin"`（不加 allow-scripts） | ¥5.55 / `S5 frame-busting` | 一笔 ¥5.55；不加 sandbox 时同一页会被弹回 |
| S6 滚动后重定位 | 长页滚动到底部才对齐目标按钮，规避顶部警惕 | 覆盖层固定定位跟随滚动 | ¥6.66 / `S6 scroll` | 一笔 ¥6.66；不滚到底点不动 |
| S7 移动端 tapjacking | 移动视口 + 大号触摸按钮，靠误触完成点击 | 移动视口、触摸输入 | ¥8.88 / `S7 tapjacking` | 一笔 ¥8.88 |

## 演示时怎么说（三句）

1. 点之前：`这一招是 S5，区别在于它绕过了目标的 frame-busting——页面加了 sandbox 禁掉目标脚本。`
2. 点下去：`点击是受害者本人按下的，浏览器给的是可信手势，所以服务端完全合规。`
3. 点之后：`看受害者的交易记录：备注写着 S5 frame-busting、金额 ¥5.55。七招金额互不相同，所以每条记录都能反查是哪一招打的。`

## 证据在哪

- 每招的金额与备注：页面顶部"台账指纹"标签 + 受害者「交易记录」备注列
- 每招的手法说明：页面顶部"Sx 的手法"一行
- 每次运行的技术参数与事件流：`artifacts/attacker/runs.jsonl`
  （`params.opacity`、`iframe_width/height`、`offset_x/y`、`decoy_text`，事件为 `page_ready` → `iframe_load` → `victim_action_reload` → `run_complete`）
- 受害者侧两条信号通道：CSP `frame-ancestors` 报告、iframe 内点击（`in_frame` / `trusted` / `since_focus_ms`）

## 已知边界（被问到就说这个）

- 七招**没有**进自动实验矩阵：`config/experiments.yaml` 目前只跑 S2，变量是 28 种防御配置。手法对比靠手工场景页 + `runs.jsonl`，不是靠矩阵数据。
- 台账指纹是**演示与复盘用**的标注，不参与攻击成功判定；判定仍以"业务状态是否变化"为准。
